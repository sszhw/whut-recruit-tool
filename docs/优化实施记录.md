# 优化实施记录（对照《架构与网页功能优化建议》）

本文记录建议文档的实际落地情况、验证方式与后续待办。日期：2026-09-16。

## 一、本次已实施

### 1. 统一招聘主数据口径（建议 §2.1 / §7，P0）

新增 **`app/repository.py`** 作为唯一数据访问层：

- 跨 `data/` 下全部 `*_原始数据.json` 合并，按学校网站 ID 去重（新文件优先，按 mtime 判定）；
- 按「文件列表 + mtime_ns + 大小」签名做进程内缓存，数据文件变化自动失效；
- 提供 `aggregate()` / `master_summary()`（记录数、覆盖日期、最近更新、详情缺失）、
  `companies()`（企业清单）、`unanalyzed()`、`health()`。

接入点（原先各读各的文件，现已统一）：

| 位置 | 改造前 | 改造后 |
|------|--------|--------|
| 招聘 / 双选会列表（`server.load_recruitments` / `load_fairs`） | 自己 glob 合并 | `repository.raw_items("recruit"/"fair")` |
| 宣讲会列表（`server.load_preachs`） | 只读最新一个宣讲会文件 | `repository.raw_items("preach")` |
| 企业分析（`analyze.py`） | 默认只读**最新**一个文件 | 新增 `--merge`（Web 端默认开启），合并去重后分析 |
| 投递推荐（`resume.build_companies`） | 只读最新文件，上限 60 家 | 主库全量候选排序后再按上限送入 LLM，并回报真实总量 |

**实测效果**（本项目真实数据）：主库 = 招聘 **1858** 条 / 双选会 37 条 / 宣讲会 **759** 场 / 企业 **962** 家；
改造前企业分析与推荐只看「最新那个文件」，候选范围远小于页面展示。缓存使重复请求从 0.47s 降到 0.006s。

### 2. 后台任务持久化（建议 §2.4，P1）

- 任务记录落盘 `data/任务历史.json`，每个任务独立日志 `data/任务日志/<task_id>.log`；
- 状态机 `queued → running → succeeded / failed / cancelled`，含进度（解析子进程 `[3/120]`、`已抓取详情 8/40`）、
  失败摘要（从输出中提取错误行）、开始/结束时间、耗时；
- 服务重启后历史任务仍可查看，`GET /api/task/<id>/log` 自动回落到日志文件；
- 任务 ID 改为 ASCII 前缀 + 毫秒 + 冲突自增（`crawl_…` / `analyze_…` / `flow_…` / `preach-check_…`）。

### 3. 可靠性修复（建议 §4 P0「修复错误提示、任务失败展示和输入校验」）

- 统一 JSON 错误响应：`/api/*` 的 4xx/5xx 一律 `{ok:false, error}`，未捕获异常也转 JSON 并写服务端日志；
- 抓取日期校验（格式 + 开始不能晚于结束）；`/api/task/stop` 缺参校验；
- `/api/status` 的「是否已配置 Key」改为跟随当前 LLM 提供商（此前固定看硅基流动字段，切到其它厂商会误报未配置）。

### 4. 网页功能（建议 §3.1 / §3.2 / §3.9，P1）

- **今日行动中心**（首页）：今日新增招聘 / 近 3 天宣讲 / 今日宣讲 / 我的收藏 / 待分析企业 / 主库条数，
  卡片可点击并自动套用筛选（`/api/actions`）；
- **数据健康**（首页）：最近更新时间、主库条数（含文件数）、覆盖日期、详情缺失、已/未分析企业、
  工作地未确定（`/api/health`）；
- **统一任务中心**（顶栏抽屉）：运行中徽标、进度条、停止、日志折叠、历史列表（`/api/tasks`）；
- **招聘信息列表**：搜索扩展到正文、只看今日新增、按单位排序、今日新增条数提示；
- 任务完成后自动刷新当前页数据。

### 5. 工程化与测试（建议 §2.9，P0）

- `tests/`：47 个用例覆盖 跨文件合并与 ID 去重、缓存失效、宣讲会筛选、推荐（城市/性质过滤 + 离线兜底）、
  Markdown 报告导入、ICS 转义与折行、任务管理器（进度/日志/持久化/失败/取消/并发）；
- `pyproject.toml`：pytest（`testpaths` / `pythonpath`）+ ruff 配置；
- 测试使用 `tmp_path` 隔离，不触碰项目真实数据。

**测试过程中发现并修复的两个真实缺陷**：

1. `TaskManager.start()` 在持有**不可重入** `Lock` 时调用 `public()` → 死锁（一旦启动任何任务，该类型任务接口即永久挂起）；
2. 任务 ID 只用「类型 + 秒」生成，同一秒内启动的不同类型任务会**共用 ID**，
   导致内存记录与日志文件互相覆盖 → 改为毫秒 + 冲突自增。
